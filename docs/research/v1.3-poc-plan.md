## 1. Architecture

```
UNPRIVILEGED GUI
    load/create persistent <FCT_UID>   (identity, not a credential)
    bind http://127.0.0.1:<ephemeral>/
    HTTPS :1001 bootstrap (send <FCT_UID>)
    SystemBrowserLauncher → https://<GATEWAY>:1001/saml?<16-hex>
    WAITING_FOR_AUTH
    GET /?tokenid=<FCT_TOKEN_ID>&username=<USER>
    credentials IPC → helper
        psk, username=<FCT_UID>, password=<FCT_TOKEN_ID>
        never argv; wipe GUI copy after send

PRIVILEGED HELPER
    UDP 500/4500 ownership check (existing)
    0600 secrets.conf: ike-psk + eap { id, secret }
    swanctl IKEv2 + local-eap (eap-mschapv2, eap_id=<FCT_UID>)
    private charon  /run/charon.fvl.conf  /run/charon.fvl.vici
    fvl-forticlient-vid plugin on IKE_SA_INIT only (IKEv2 SSO)
    initiate → Mode Config VIP → CHILD_SA
    wipe secrets on success, failure, and disconnect
```

SAML runs **before** IKE. Helper `auth_mode` stays `standard` for this
path: `auth_mode=saml` is the SSL/openfortivpn flow (**CODE**). Do not
put `token`, `cookie`, or `saml` on the helper connect JSON
(`FORBIDDEN_REQUEST_KEYS`).

## 3. Helper protocol changes

Current (**CODE** 0.9.0 capability token; `protocol_version` 1):

- Hello advertises `capabilities`: `ipsec_ikev1_psk_xauth`,
  `ipsec_ikev2_eap`. A missing list means a v1.2 helper.
- Connect JSON: no secrets. Forbidden: `cookie`, `token`, `tokenid`, `saml`, argv.
- Follow-up `credentials`: `psk`, `username`, `password`.
- IKEv2 SSO reuses the same keys:
  - `psk` — IKE tunnel PSK
  - `username` — `<FCT_UID>` (EAP Identity, **not** `<USER>`)
  - `password` — `<FCT_TOKEN_ID>` (ephemeral EAP-MSCHAPv2 secret)
- Packaged 1.2.0 helpers remain 0.8.0 and do not advertise IKEv2 EAP.
  The GUI must fail that mismatch at probe (`HELPER_VERSION_MISMATCH`
  and/or `HELPER_CAPABILITY_MISMATCH`) instead of sending IKEv2 connect.

## 4. GUI / backend state

Existing SSL SSO machine is reused, IPsec-specific transitions:

```
DISCONNECTED
    → STARTING          (UID ready, listener bound, :1001 bootstrap)
    → WAITING_FOR_AUTH  (browser open; wait for GET tokenid)
    → CONNECTING        (credentials to helper; private charon; initiate)
    → CONNECTED
```

Cancel / timeout / browser failure from `WAITING_FOR_AUTH`:
`DISCONNECTING` → wipe any tokenid in memory → `DISCONNECTED` or `FAILED`.
Helper is not started until tokenid is in hand.

Do not start IKE during the browser wait (**PROVEN** SAML-before-IKE).

## 6. Localhost callback lifecycle

New unprivileged module (planned `vpn/ipsec/saml_listener.py`):

1. Bind `127.0.0.1` ephemeral port **before** `:1001` bootstrap so the
   start URL / FortiGate redirect can target it.
2. Accept one `GET /?tokenid=&username=`.
3. Respond with a short static HTML success page (no secrets).
4. Close the listener.
5. Timeout (FortiClient uses 300 s; PoC may reuse the existing SAML wait
   timeout unless a dedicated constant is added).
6. Parse **only** `tokenid` and `username`. Treat missing `tokenid` as
   auth failure.

`username` (`<USER>`) may be shown as a non-secret display hint after
redaction rules; it is **not** sent as EAP identity or EAP password.

## 8. `<FCT_TOKEN_ID>` secret lifecycle

| Stage | Handling |
| ----- | -------- |
| Birth | Query string on localhost GET only. |
| Memory | Single object, not copied into profile, Qt widgets, or log buffers. |
| IPC | Helper `credentials.password` over the existing privileged socket. Not argv. |

**Profile editor / model (Slice 1 live-test prep, not Slice 2).**

User-facing IPsec authentication is a workflow, not a protocol acronym:

- **Pre-shared key + username/password** — existing IKEv1 PSK + XAuth.
- **Single Sign-On (SSO / SAML)** — internally IKEv2 + EAP + EAP-MSCHAPv2
  + SAML pre-authentication. The editor may show read-only
  “Protocol authentication: EAP-MSCHAPv2”. Application logic never
  compares translated display strings.

SSO Connect routing (Connection page, Profiles page, tray) skips the
legacy PSK/XAuth dialog. If the tunnel PSK is not already stored, a
PSK-only prompt is used. EAP secrets come from SAML, not that dialog.

The IPsec tunnel still has a pre-shared key. Slice 2 consumes it as the
IKE PSK after SAML. Switching the editor to SSO must not destroy a
stored PSK.

Multiple IKE and CHILD_SA proposals plus multiple DH groups are now
representable as structured lists (`ike_proposals`, `ike_dh_groups`,
`child_proposals`, `pfs_dh_groups`). Legacy singular fields stay
dual-written on save. Load precedence: non-empty list fields win;
otherwise singular fields migrate to a one-item list. Loading never
rewrites the file.

New IKEv2 SSO profiles default to the known-good FortiClient reference
(port 500, Mode Config, AES128/SHA256 + AES256/SHA256, DH 20+21, IKE
lifetime 86400, CHILD AES128/SHA1 + AES256/SHA256, lifetime 43200, PFS
group 20, NAT-T, DPD, replay, SAML port 1001). Legacy IKEv1 defaults are
unchanged.
