# Security Policy

## Supported versions

This project is in early development (v0.3.x). There is no stable VPN client
release yet. Security reports are still welcome.

| Version | Supported |
| ------- | --------- |
| 0.3.x   | Yes       |
| 0.2.x   | Yes       |
| 0.1.x   | Yes       |

## Reporting a vulnerability

Please report security issues privately through
[GitHub Security Advisories](https://github.com/TimeWizard007/fortigate-vpn-linux-gui/security/advisories/new).

Do not open a public issue for vulnerabilities that could put users at risk.

Include:

- a description of the issue and its impact
- affected version or commit
- steps to reproduce, if possible
- any suggested fix

We will acknowledge reports as soon as practical and keep you informed while we
investigate.

## Security principles

These rules apply now and to future VPN, SAML, and helper work:

1. **The GUI must never run as root.** The application refuses to start with an
   effective UID of 0. Future privileged work belongs in a minimal helper, not
   in the desktop process.
2. **VPN passwords must never be stored in plaintext.** When credential storage
   is added, it must use a platform secret store (for example the FreeDesktop
   Secret Service), not a config file in `~/.config`.
3. **SAML tokens and cookies must never be written to logs.** Authentication
   material from Microsoft Entra ID or the FortiGate SSO flow must not appear
   in log files, diagnostics dumps, or screenshots generated by the app.
4. **Privileged operations will use a minimal helper / polkit design.** The GUI
   will not call `sudo`, install system services, or change routes, DNS, or
   firewall rules by itself.
5. **Logs must redact credentials and authentication material.** Passwords,
   tokens, cookies, authorization codes, and similar secrets must be stripped
   or replaced before anything is written to disk or shown in the Logs page.
6. **Certificate verification must not be silently disabled.** Users must never
   be opted into `trusted-cert` (or equivalent) without an explicit, visible
   choice and a clear warning. Insecure defaults are not acceptable.

## Current scope (v0.3.x)

v0.3.x starts `openfortivpn` as the current user with
`openfortivpn <gateway>:<port>` (list argv, `shell=False`, no credentials).
It does not perform SAML authentication, invoke sudo/pkexec, or modify the
network itself. Connection profiles are stored as local JSON without
passwords, SAML tokens, cookies, or other secrets. Backend log lines are
redacted in memory. The principles above still constrain how SAML and a
privileged helper will be added.
